# 主动采集型网关接入说明

## 推荐模式

优先使用支持本地 Modbus 主站轮询和 MQTT JSON 上报的网关，例如 USR-G770 轻边缘版这一类设备。

推荐链路：

```text
两台流量计 -> RS485/Modbus RTU -> 网关本地轮询 -> MQTT JSON 上报 -> EMQX -> 后端
```

服务器不主动下发查询指令，只负责接收和保存数据。

## 网关必须确认的能力

- 可作为 Modbus RTU 主站
- 可配置两个从站地址
- 可配置功能码、寄存器地址、数据类型和倍率
- 可配置采集周期，建议 30 秒或 60 秒
- 可上报到自建 MQTT Broker
- 可上报 JSON payload
- 支持 NTP 校时
- 支持断线重连

优先确认：

- 是否支持断线缓存补传
- 是否支持 TLS
- 是否支持配置导出和恢复

## 建议 topic

```text
meters/FM001/reading
meters/FM002/reading
```

也可以统一上报到：

```text
meters/{meter_id}/reading
```

后端默认订阅：

```text
meters/+/reading
```

## 建议 payload

```json
{
  "meter_id": "FM001",
  "device_ts": "2026-05-20T10:15:00+08:00",
  "instant_flow": 12.34,
  "total_flow": 56789.01,
  "unit": "m3/h"
}
```

字段说明：

- `meter_id`：流量计编号，例如 `FM001`、`FM002`
- `device_ts`：网关采集时间，必须带时区
- `instant_flow`：瞬时流量
- `total_flow`：累计流量
- `unit`：单位，默认 `m3/h`

## 两台流量计建议配置

| 流量计 | Modbus 从站地址 | MQTT meter_id |
|---|---:|---|
| 1号流量计 | 1 | FM001 |
| 2号流量计 | 2 | FM002 |

实际寄存器地址、数据类型和倍率需要以流量计说明书为准。

## 字段不一致时的处理

如果网关可以上报 JSON，但字段名、层级或寄存器倍率和推荐 payload 不一致，不需要改后端代码。

进入前端 `网关配置` 页面，新增一条解析配置：

- `Topic 匹配` 填网关实际上报 topic，支持 `+` 和 `#`
- `表号 JSON 路径` 填 payload 内表号字段，例如 `meterId`
- payload 没有表号时，使用 `表号 Topic 段序号` 从 topic 提取
- `设备时间路径`、`瞬时流量路径`、`累计流量路径` 填 JSON 字段路径
- 原始寄存器值需要换算时，填写 `瞬时流量倍率` 和 `累计流量倍率`
- 粘贴一条真实 payload 到 `样例 Payload JSON`，点击 `测试解析`
- 网关已经上报过数据时，可从 `最近原始 Payload` 直接套用样例

示例：

```json
{
  "meta": {
    "meter": "FM002"
  },
  "time": {
    "ts": "2026-05-20T10:15:00+08:00"
  },
  "values": {
    "flow_raw": 123,
    "total_raw": 567890
  }
}
```

对应配置：

| 配置项 | 值 |
|---|---|
| Topic 匹配 | `gateway/+/data` |
| 表号 JSON 路径 | `meta.meter` |
| 设备时间路径 | `time.ts` |
| 瞬时流量路径 | `values.flow_raw` |
| 累计流量路径 | `values.total_raw` |
| 瞬时流量倍率 | `0.1` |
| 累计流量倍率 | `0.001` |

## 数据处理规则

`网关配置` 页面还可以调整运行期处理规则：

- `时钟偏差阈值 秒`：超过后原始数据入库，但状态标记为 `clock_skew`，不参与正式 15 分钟汇总
- `离线判定阈值 秒`：超过后实时状态标记为离线
- `15分钟最少样本数`：低于该数量的 15 分钟窗口标记为 `gap`

这些配置写入数据库，保存后立即生效，不需要重启容器。

## 如果网关只能透传

如果设备只支持透传模式，不支持本地 Modbus 轮询和 JSON 上报，那么服务器端需要改成主动轮询：

```text
后端生成 Modbus 查询帧 -> MQTT 下发给网关 -> 网关透传到 RS485 -> 流量计响应 -> MQTT 回传 -> 后端解析
```

这种方式可行，但后端复杂度更高，需要处理：

- Modbus RTU CRC
- 请求/响应匹配
- 超时和重试
- 串行轮询
- 两台从站地址冲突
- 断线后补传困难

所以本项目优先选择主动采集型网关。
